### 14.16 配套代码与本地验证 — 2026-11-14

用户进一步要求编写配套代码和启动脚本。本次在同一独立分支 design/lm-head-only-20261114 实现，工作副本为 VSCode下载/New/nanogpt-lm-head-design-20261114。新增包 nanogpt_noise/lm_head、脚本 scripts/run_lm_head.sh 和启动说明 LM_HEAD_RUN.md。原 main 分支、v1.8 源码和 last-k 入口未改，Obsidian 与服务器未操作。

实现覆盖完整 Head 的 G/T/K 目标、同值解除共享、Muon-head、八候选搜索、单卡动态队列、暂停恢复、真实 validation CE 评价、赢家权重保留和成对排序汇总。Hessian 入口使用完整词表概率构造 FP64 主子块，输出全 trace、纳入概率校正谱矩、局部谱、梯度奇异值、固定完整 batch 梯度波动和 Taylor 误差。K 训练必须读取初始化拟合与独立留出检查通过的冻结产物；后期 checkpoint 只测漂移，不能生成新的可训练 K 产物。

本次把以下实现细节显式登记，训练配方和研究阈值维持 draft2：

- 两种参数布局分别使用基础参数 seed 加 100×布局编号的独立流，布局编号为 0、1；基础 seed 仍为拟合 2026111411、留出 2026111412。扩展拟合块数保留各布局已抽块的前缀；后期每种布局使用初始化最先抽到的两块。
- 数据探针预留两池各 128 个不重叠窗口，再取所需前缀，以保证 32768、65536、131072 tokens 扩样时保留前缀，且两池不因扩样重合。窗口位置与参数索引均写入身份清单。
- 梯度波动采用原训练索引步骤 0–15 的完整 batch；预定随机方向 seed=2026111421。拟合检查 batch 均值，留出检查固定 train/val 评估池的均值。
- B 的数值零空间诊断阈值为最大特征值的 1e-12，梯度相对投影容差为 1e-8；公共 logits 平移方向同样检查。该阈值只用于报告和验收，不截断特征值、不投影训练梯度、不添加 ridge。
- 后期测量默认每种布局两块拟合与两块留出；后期结构误差保留为漂移，不重做初始化代理验收。初始化 K 的 block 中位误差按通常的中位数定义计算，偶数块取中间两值的平均。
- 新运行目录绑定代码、输入和实验身份；候选还绑定目标、micro batch、软件与 K 文件哈希。G clean 保存规定分析快照；每个搜索结束后压缩日志、保留 CE 赢家完整包，另存需要的训练目标赢家 Head，并生成保留文件哈希清单。

本地验证合计 138 项通过，7 项 Linux/POSIX 专属检查在 Windows 跳过。其中新增 12 项 Python 数学/恢复/流程测试、4 项 Bash 路由测试。覆盖完整 Head 作用范围、T 的起点梯度与 Hessian、K 起点梯度与结构 Hessian、解析块和校正谱矩、12 组目标×优化器逐值恢复、四优化器 B=8 队列与重放、留出门槛、后期漂移及启动路由。首次全量扫描中的 30 项旧 Bash 测试因 Windows Apps 占位入口报错；显式使用 Git Bash 后这 30 项全部通过。最终统计按不同测试项计数，不将复跑重复计入。

这些检查采用合成小模型和 CPU PyTorch 2.9.1，不是新优化器性能结果。目标 GPU BF16、完整 50304×768 Head 的显存/耗时、Linux 硬中断和实际存储容量尚待验收。smoke 保存同步分项计时与峰值显存，正式运行仍需先通过对应目标的四优化器 32 步 smoke。本次没有启动正式训练或验证服务器当前运行状态。

GitHub 的 20261114-draft2 目录保留原设计发布快照及其哈希；实现说明、验证记录与实现清单另存于该实验的上级目录，不回写历史快照。主设计仍以本文件为唯一编辑来源。

### 14.17 LM Head micro batch 调整 — 2026-11-14

用户要求按 micro_batch_adjustment_guide.md 修改代码、启动脚本和仓库说明。本节将指南中的运行布局决定纳入唯一主设计，适用范围仅为独立 LM Head 实验；原 last-k 设计和运行代码保持不变。

LM Head 的 Python 训练、队列、CLI、离线曲率入口和 Bash 默认 micro 统一改为 16；显式参数仍可覆盖。正式全局 batch 始终为 512 条序列、每条 1024 tokens，单卡累积次数为 512/micro：micro=16 时累积 32 次，micro=32 时累积 16 次。每步 524288 tokens、3815 步、调度、LR 搜索、随机流、BF16/FP32 口径及累积后统一注入一次噪声均保持不变。

同一实验运行根目录将 micro 写入不可变身份；G/T/K 共用同一个值。跨目标报告逐候选核对 execution.micro 与根目录身份，不接受缺失或不同的 micro。已有候选继续保留原 micro 和代码身份约束，不允许换 micro 续训；缺少 micro 的旧根登记不自动补写或迁移。调整只用于全新目录，已启动的旧实验继续使用原冻结 checkout。

本次保留 T/K 的原有计算图和梯度累加顺序。T 的完整词表中间张量随 micro 增大而增加显存，K 的固定二次项仍按原实现逐 micro-batch 计算；不在本次改动中把二次项移出累积循环。不同 micro 的浮点结果不保证逐位一致，不能混作同一配对实验。

固定评估池各 200 条序列，micro=16/32 的最后一块均为 8 条；汇总继续按实际序列数以 FP64 加权。离线特征、曲率和固定 16 个完整训练 batch 的梯度诊断需覆盖尾块测试。tiny 测试显式使用兼容其 batch=4 的 micro=2 或 4，不改变正式默认值。

H100 选档使用独立临时目录分别测 micro=16 和 32，每档对 G/T/K 的四优化器各执行 32 步 smoke。K 仍须先获得通过几何验收、绑定当前代码和输入的统计产物，不能伪造通过标记来测速。检查 performance.json 的 wall_seconds、分项时间及 peak_allocated_bytes；三目标均通过后再选择共同档位。默认 16 只是待硬件验证的起点，不代表已经优于 4 或 32。

选档后在全新的正式输出根目录固定该 micro，重新生成各目标的正式 smoke 凭证再运行 clean。测速目录、失败档位和未完成的 K 保留明确状态，不自动选档、降档、清理旧目录或启动训练。本次交付为代码、脚本与仓库说明的修改和本地验证；服务器实测与正式启动另行执行。

本地验收新增 8 项 Python 检查和 1 项 Bash 路由检查，均通过。最终完整回归 154 项中 147 项通过、7 项 POSIX 专属检查在 Windows 跳过，耗时 314.299 秒。首次全量运行有一项未修改的旧队列测试因线程完成顺序断言失败；该项单独连续 10 次复跑通过，随后完整回归通过，首次记录保留。测试覆盖默认值、跨目标 micro 拒绝、旧根登记拒绝、改变 micro 续训拒绝、200 条评估的尾块、16 个完整 batch 梯度诊断，以及 micro=16/32 的冻结特征和 Hessian 子块数值对照。T/K 算子、原优化器和噪声实现逐文件核对未改；CPU 检查不替代 H100 验收。
